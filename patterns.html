Design patterns I like.

Applied to a higher-stakes judgement flow: Account Collections.

The patterns

Family A. Making the agent legible
Intent preview
The agent shows what it's about to do before doing it. Recipient, content, tone, and confidence at a glance, with explicit buttons to send, edit, skip, or take it over.
Confidence + evidence
Calibrated bands instead of false-precision percentages. Supporting evidence sits inline rather than behind a hover, so the user can verify any score without leaving the surface.
Explainability on demand
A "why" surface available when the user asks. Shows what was inferred, the data that was used, and the alternatives the agent considered and rejected.
Reversibility
A recovery path for every agent action. For things that can't be literally undone, like a sent email, the agent drafts the correction in its own voice and takes responsibility.
Family B. Where the agent lives
Inline microinteraction
Small contextual cards that surface the agent inside the user's normal workflow. They live in the row, the report, the table cell, wherever the user already is, instead of asking them to navigate to a separate destination.
Side panel, console
A persistent home for the agent's state. Goal, queue, progress, and autonomy distribution live here permanently. The user returns to it across sessions. It's a state surface, not a chat.
Proactive nudge
Behavioral signals the user didn't ask for, in a low-claim tray. Snooze and dismiss are first-class affordances, and the agent silences its own categories of nudge if they keep getting ignored.
Family C. Calibrating the partnership
Autonomy dial
Per-task control over how independently the agent acts. Earned rather than configured: the system suggests dial-ups when reliability is demonstrated, the user approves them.
Sandbox, what-if
A non-committing simulation. The agent runs the full pipeline against real data with no external effects, so the user can evaluate before any commitment.
Role-based approval
Different surfaces for different stakeholders, built on the same underlying data. Working surface for the operator, outcome surface for the buyer, decision surface for the reviewer.
Hybrid intent → manipulation
Language for ambiguous intent, direct manipulation for precise refinement. Edit means both at once: a real composer, with an "ask the agent" input alongside it.

03 Explainability on demand

The why panel surfaces what the agent inferred, what data it used, and what alternatives it considered and rejected. The third part is what makes the explanation feel like an audit log rather than a sales pitch.

Why send firmer follow-up to Globex?
INV-0934, $28,400, 38 days late
Aura
Inferred
Globex is in a payment slowdown. Their AP contact recently changed, and the friendly nudge sent 14 days ago hasn't been replied to.
Used data
AR aging, contact change log, 12 months of payment history, CSM health signal, prior touch outcomes.
Considered and rejected
×   Repeat friendly nudge. Rejected because the prior nudge is already 14 days old without a reply.
×   Escalate to AE. Rejected because the invoice sits under the $50k AE escalation threshold.
×   Pause shipments. Out of scope — that's a CFO decision, not an agent one.

07 Proactive nudge

A "things Agent noticed" tray catches behavioral signals: contact changes, payment-pattern shifts, dispute spikes. It sits separately from the action queue because nudges don't always have a clear next step. Each one has a snooze affordance, and the agent silences its own categories of nudge if they keep getting ignored.

Things Aura noticed today, 3
Globex's AP contact email started bouncing yesterday. Pause sends until verified.
AcmeCo paid the last 2 invoices in 60 days versus a 38-day historical average. Likely a payment slowdown.
Hooli has 3 open disputes this quarter, up from 0 last year. Worth flagging to CSM.
Aura silenced "small-balance unmatched payment" alerts after 3 ignored. undo

Family C. Calibrating the partnership

How the user and the agent share control over time. Maturity model, shadow week, dual stakeholder surfaces, hybrid edit flow.

08 Autonomy dial

The maturity model rendered per customer. Each stage transition is earned by demonstrated reliability rather than scheduled. Agent proposes dial-ups when a customer's track record warrants it, and the user approves.

09 Sandbox, what-if

Shadow week mode runs the full agent pipeline against real data: drafting, scoring, prioritizing. Nothing leaves the system. The buyer evaluates the agent against their own book before any external sends, and the reviewed-draft volume earned in shadow mode counts toward the first stage transition.

11 Hybrid intent → manipulation

Edit means both at once. A real composer for word-level changes, with an "ask AI" input next to it for intent-level changes like "make it firmer" or "mention the ship pause." The user switches between language and manipulation depending on the situation. Without this, the four edits per batch become the bottleneck.
